## SEAPATH 2.0
Released today
Based on latest LTS of Debian 13 and Yocto Project Wrynose
Use of Cephadm
First support of container with cluster mode
- Podman
- HA with Pacemaker
- Data sync with Ceph RBD
CI/CD pipeline to generate daily/weekly releases

Erwann Roussy (maintainer) presented the new CI/CD pipeline
- Build of all the SEAPATH images (Deb, Yocto, installer)
- Reuse of the already existing GitHub Actions of SEAPATH repository
- New seapath.releases.org repository which contains all the SEAPATH release files (per version), pushed automatically by the pipeline
- New images based on the latest repository revision will also be released
- New virtual cluster tool: used to setup a SEAPATH cluster in a fully virtualized environment
	- Used for now test that the cluster deployment run well
	- In the future will also test the VM deployment in cluster
	- Will be triggered on each PR of Ansible repo
	- Latency and SEAPATH standalone test will be kept on a physical machine

Question from Stefan Richter:
Do we still support the 1.2.0 SEAPATH version?
Raise questions to be voted on the next TSC:
- Drop of ceph-ansible in favor of cephadm
- Drop of Debian 12 support
- Drop of Yocto Scarthgap support
Raise also the problem of the current limited resources to keep the support for all SEAPATH versions. Voluntary companies are welcomed to offer support of these version.

Florent confirmed that all the time for the future will be dedicated for 2.0 version.

David MacDonald : Question of the long term support of SEAPATH compared to other product which offers 10 years support

There will be a public announcement of the 2.0 release.

## SEAPATH roadmap workshop
Organized by RTE and SFL at RTE Campus May 21-22
- 45 participants
- 19 compagnies
4 topics:
- LTS support
- Project lifecycle
- Future features
- SEAPATH maintenance

32 actions proposed with 18 leaders. Some of them still don't have leaders.
Collaboration work: feel free to contribute it (leaders, contributors).

Actions:
- Business model
	- Evolution of TSC governance
	- SEAPATH demonstration platform + sandbox
	- Definition of SEAPATH scope
	- Release weekly/daily
	- Set up a user forum
	- HW/SW certification
- Project Lifecycle
	- Release : Clarify and Give visibility
	- Refactor CI/CD
	- Improve SEAPATH installer
	- Study how we can extract configuration from SCD file for SEAPATH
	- Use documentation as a code
	- Add testing applications for OT Engineers
- Enhance user experience
	- Develop a supervision tool of the virtualization infra for maintenance purposes - Prometheus integration
	- Display alerts and expose it for maintenance purposes and post morthem analysis
	- Develop a tool helping the generation of iso files/ansible inventory and vm XML configuration files
- Develop OT related SEAPATH functionalities
	- Develop IEC61850 SV broker with filtering/monitoring TBD capabilities
- Others
	- Provide a way to run containers besides SEAPATH
	- Change ressource allocations place from VM XML to centralized place
	- Provide a guideline for virtual function developments
- SEAPATH maintenance
	- No leaders for the moment
